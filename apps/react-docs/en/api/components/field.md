# Field

## Description

As the React implementation of [createField](https://core.silver-formily.org/api/models/Form#createfield) from `@silver-formily/core`, it is a bridge component dedicated to binding a ViewModel to an input control. See [IFieldFactoryProps](https://core.silver-formily.org/api/models/Form#ifieldfactoryprops) for the Field component props.

The name attribute is required.

`Field` uses the same lifecycle handling as `ArrayField`, `ObjectField`, and `VoidField`. Synchronous StrictMode effect replay does not emit extra `onFieldMount` / `onFieldUnmount` events. Replacing the field instance or actually unmounting it still performs cleanup. Real unmount cleanup is deferred to a microtask, so do not synchronously read `unmounted` immediately after removing the component to determine whether cleanup has finished.

:::tip
Only `component` / `decorator` tuple props are forwarded to their components; arbitrary top-level Field props are not spread into UI components. Data fields inject `value`, `onChange`, `onFocus`, and `onBlur`. Each event updates the model before calling the latest matching component callback. Explicit component `disabled` / `readOnly` props override the defaults derived from the field pattern. Adapt checkbox-like value props with `connect` / `mapProps` when necessary.
:::

Both `hidden` and `none` suppress rendering. Core retains values for `hidden`, while `none` removes values and restores cached values when shown again. The field model's mount lifecycle is distinct from whether its inner UI is visible.

Children from `children` (including its render-function result) are combined with `field.content ?? field.componentProps.children`; zero is valid content. A field without a component still renders its content. Component and decorator references can be intrinsic tag names or React components; schema registry names are resolved through `SchemaComponentsContext`.

Core declares `title`, `description`, and `content` as `any`; values placed in the rendered React tree must still be valid ReactNode values. Display/pattern defaults in the table assume no overriding parent or form state.
