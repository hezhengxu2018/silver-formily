# React Guide (extends root `AGENTS.md`)

This package is the React 18/19 form rendering layer for Silver Formily, migrated from `@formily/react@2.3.7` (upstream `formily_next` branch). Follow the global conventions defined in the repository root, then apply the details below when working inside `packages/react`.

## Source Layout

- `src/components/` holds the field components (`Field`/`ArrayField`/`ObjectField`/`VoidField` all render through the internal `ReactiveField`), `createSchemaField`, and the scope components.
- `src/hooks/` holds the public hooks plus the internal `useAttach` (mount/unmount lifecycle bridge).
- `src/shared/` holds the React contexts, `connect`/`mapProps`/`mapReadPretty`, and the internal `render` portal helper.
- `src/index.ts` re-exports `@silver-formily/json-schema` in full—do not drop that line, consumers rely on `Schema`/`ISchema` coming from this entry.
- `dist/` is generated by tsdown (`pnpm build`). Treat it as read-only—changes there will be discarded.

## Upstream Divergence

Deliberate differences from `@formily/react` — keep them when syncing upstream changes:

- All imports point at `@silver-formily/*`; `FormPath` comes from `@silver-formily/path` (the fork split it out of `shared`), imported as `import { Path as FormPath } from '@silver-formily/path'`.
- `useAttach` / `useFormEffects` call `useCompatEffect` / `useCompatFactory`—the reactive-react fork dropped the `unstable_` prefix.
- Peer dependencies are `react`/`react-dom` `^18 || ^19` plus the internal `@silver-formily/*` packages; upstream's `react-is` peer was dropped (nothing in the source uses it).
- `JSXComponent` uses `React.JSX.IntrinsicElements` because `@types/react@19` removed the global `JSX` namespace.
- `shared/render.ts` imports `createPortal` from `react-dom` at the top level; the upstream `globalThisPolyfill` + `require()` + dynamic-import fallback chain was removed. SSR (no `document`) still falls back to rendering a `<template>` element.
- Upstream `src/global.d.ts` (the `Formily.React` global namespace for UMD builds) is not migrated—this fork publishes ESM only.
- ESM-only output in `dist/` (`.mjs` + `.d.ts`), built with tsdown instead of upstream's `tsc + rollup` combo.
- The package uses the automatic JSX runtime (`jsx: react-jsx`, overridden in this package's `tsconfig.json`); value imports from `react` are named imports (`createElement`, `Fragment`, ...).

## Commands

| Script                      | When to run                                                    | Notes                                                                         |
| --------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `pnpm build`                | Before publishing or when other packages need fresh artifacts  | Runs tsdown to emit ESM + d.ts into `dist/`.                                  |
| `pnpm dev`                  | Local development                                              | `tsdown --watch`; re-builds on change, but still writes into `dist/`.         |
| `pnpm test`                 | Before merging behavior changes                                | Vitest browser mode (Chromium via Playwright); `test:coverage` runs headless. |
| `pnpm check-types`          | Whenever TypeScript config changes or you see editor anomalies | Uses plain `tsc --noEmit` (no `vue-tsc` here).                                |
| `pnpm format` / `pnpm lint` | Required before commits                                        | Delegated through root Turborepo tasks to ensure ESLint passes.               |

## Testing & Verification

- Tests run in a real browser via Vitest browser mode (see `vitest.config.ts`): Playwright provider, Chromium instance, `vitest-browser-react` for rendering.
- `render`/`rerender`/`unmount` from `vitest-browser-react` are async—always `await` them. Assertions use locators (`await expect.element(...)`), which auto-retry and absorb reactive re-renders—no manual `act()` wrapping is needed.
- Query APIs come from the returned `screen` object (`screen.getByTestId(...)`); negative assertions use `.not.toBeInTheDocument()`, and raw DOM access goes through `await locator.element()`.
- `tests/shared.tsx` hosts the `ErrorBoundary` helper; upstream specs that depended on `antd` / `@ant-design/icons` use local stand-in components defined at the top of `tests/schema.json.test.tsx`.
- Tests resolve `@silver-formily/*` through their built artifacts (Turbo `test` depends on `^build`)—rebuild internal packages before debugging type errors in tests.
